# План подготовки к платному запуску

Дата аудита: 2026-09-21. Исходная ветка: `main`.

## Цель и ограничения

Цель планирования — в среднем 500 ₽ в день после денежных расходов, или
15 000 ₽ за 30 дней. Это гипотеза, не обещание дохода. Рабочее время владельца
нужно оценивать отдельно. Пока нет измеренной себестоимости и подтверждённого спроса.

Тестовая модель: 50 подписчиков × 499 ₽ = 24 950 ₽ в месяц.
Для достижения цели совокупные расходы не должны превышать 9 950 ₽ в месяц.
В них входят ИИ, транскрибация, сервер, комиссии, налоги, возвраты и привлечение.
Тариф без безлимита; квоты определяются только после замеров затрат.

Стартовая гипотеза продукта — конспекты профессиональных лекций и вебинаров
для русскоязычных специалистов: выводы, проверяемые таймкоды и Markdown-экспорт.
Первый сегмент для проверки — специалисты по маркетингу.

## Этапы и критерии приёмки

| Этап | Работа | Критерий завершения |
|---|---|---|
| 1. Исходное состояние | Тесты текущего поведения и CI | Получены результаты pytest, Ruff и Docker-сборки |
| 2. Защита обработки | Проверка доменов, лимиты текста и запросов, изоляция медиафайлов, безопасные ошибки | Недопустимые запросы не вызывают платные API; параллельные задачи не конфликтуют |
| 3. Закрытая бета | Пользователи, SQLite, сохраняемая очередь, восстановление задач, учёт затрат | Чужие результаты недоступны; перезапуск не оставляет задачи навечно в обработке |
| 4. Полезность | История, экспорт, реальные таймкоды, ввод собственного транскрипта | Конспект пригоден к использованию; таймкоды основаны на исходных сегментах |
| 5. Спрос | 10 интервью и 20 приглашённых тестировщиков | Есть первые оплаты и измерено повторное использование |
| 6. Оплата | Один тариф, квоты, проверка уведомлений, идемпотентное начисление | Повторное уведомление не удваивает доступ; сценарии отказа и возврата проверены |
| 7. Продажи | Разрешённые размещения, партнёрства, контроль удержания | Рост к 50 активным подписчикам в пределах бюджета |

## Подтверждённые кодом риски

| Область | Наблюдение | Следующее действие |
|---|---|---|
| API | Нет авторизации и квот; список задач общий | Защитить все операции, включая отдельные текстовые этапы |
| Входные данные | HttpUrl не проверяет домен YouTube; нет верхнего лимита текста | Негативные тесты и серверная валидация перед обработкой |
| Исполнение | BackgroundTasks не восстанавливается после перезапуска | Сохраняемая очередь с контролем конкурентности |
| Хранилище | Неатомарная запись JSON; нет блокировки чтения | Тесты, атомарность, затем миграция на SQLite с резервной копией |
| Медиа | Имена файлов зависят от video_id, не от задачи | Отдельный временный каталог на каждую обработку |
| ИИ | Этапы могут повторно сжимать уже сжатый текст | Тестировать число обращений; ограничить затраты |
| Распознавание | Используются ключ и URL LLM-провайдера | Разделить конфигурации LLM и транскрибации |
| Интерфейс | Опрос статуса не имеет предела ожидания | Таймаут и корректная обработка HTTP-ошибок |

До этапов защиты нельзя открывать неограниченный публичный доступ с платным ключом.
Доступность YouTube проверяется отдельно на выбранном сервере и разрешённом контенте.
При ограничении доступа — понятная ошибка и собственный транскрипт пользователя,
без обхода CAPTCHA, авторизации или ограничений платформы.

## Текущий набор изменений

| Файл | Назначение |
|---|---|
| `docs/launch-plan.md` | План, риски и критерии приёмки |
| `tests/test_youtube.py` | Проверка поддерживаемых ссылок, очистки и загрузки субтитров с заглушкой |
| `tests/test_storage.py` | Проверка сохранения, чтения, сортировки и статусов во временном каталоге |
| `.github/workflows/ci.yml` | Независимые задания pytest, Ruff и Docker-сборки |

Код приложения и API не меняются. Тесты фиксируют только часть существующего
поведения и не означают, что перечисленные риски исправлены. Новые тесты не
обращаются к YouTube или платным API. Установка зависимостей и Docker-сборка
требуют сети, но не секретов провайдера.

GitHub-коннектор записывает по одному файлу за коммит; каждый коммит использует
согласованное сообщение `test: establish launch baseline and CI`.
CI запускается на push и pull_request. Workflow добавляется последним,
чтобы первая проверка включала оба новых тестовых файла.

## Проверка

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
ruff check .
docker build --tag yt-summarizer:baseline .
```

Задания независимы: ошибки исходного линтинга не скрывают результаты тестов
или сборки. Проверки не отключаются ради зелёного статуса. При ошибках сначала
разбирается результат, затем согласуется минимальное исправление.

Проверка типов пока не настроена: требуется отдельный выбор инструмента и
базовой конфигурации. Docker-сборка не заменяет smoke-тест приложения на сервере.
Миграция данных и изменение развёртывания в этот набор не входят.

## Метрики закрытой беты

| Метрика | Зачем измерять |
|---|---|
| Успешные обработки / все обработки | Надёжность сервиса |
| Время обработки: медиана и p95 | Ожидание пользователя |
| Стоимость успешной и неуспешной обработки | Квоты и рентабельность |
| Минуты видео и источник транскрипта | Разделение дешёвых и дорогих сценариев |
| Возвращение пользователя в течение 7 дней | Повторная ценность |
| Пробные пользователи, оплаты и отток | Проверка спроса и удержания |

Полные транскрипты, платёжные секреты и API-ключи не должны попадать в аналитику.
Реальные тарифы провайдеров и юридические требования проверяются перед запуском.
